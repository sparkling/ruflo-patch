## Headline divergences

1. **The substrate the C4 plugins ride is healthy** — `memory_*` (adr-patterns / sparc-* / ddd namespaces), `agentdb_hierarchical-store/recall`, `agentdb_causal-edge/causal-query`, `task_*`, `hooks_worker-dispatch`, and all 6 `analyze_*` jujutsu tools store + recall + analyze with real content. No C4 plugin's core substrate is dead.
2. **The C2 R1 regression is INHERITED by the adr plugin's substrate** — `agentdb_causal-edge` writes ADR edges to `causal_edges` (typed `adr`, via the `adr_node_ids` numeric allocator), `graph_edges` stays **0**, so `agentdb_graph-query`/`graph-pathfinder` are starved. The adr plugin's own `adr graph` subcommand survives because it uses `agentdb_causal-query` (which reads `causal_edges` and **works**). **Same root as C2 R1 / ADR-0276 — not a new defect; re-confirmed in the ADR consumer context.** (Content-verified, full bar.)
3. **The adr plugin's own surfaces internally contradict each other on ADR format** — the `adr` *command* (`commands/adr.md`) specifies `ADR-NNN-<slug>.md` (3-digit, `ADR-` prefix, "standard template", `# ADR-NNN:` H1); the `adr-create` *skill* specifies `NNNN-<slug>.md` (4-digit, **NO `ADR-` prefix**, canonical MADR, YAML frontmatter); and the `agentdb index` builder (ADR-0273) **requires `ADR-`-prefixed files** — so a project that follows the *skill* literally produces files the canonical *index builder* refuses (`[ERROR] No ADR-*.md files`). The command is pre-ADR-0157 shape never updated. **FORK-internal doc-drift (3-way), content-verified.**
