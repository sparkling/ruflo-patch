## The central divergence axis (read first — frames every premise)

C4's hottest area is **ADR tooling** (the `ruflo-adr` plugin + the `agentdb index` CLI). The fork made a large, deliberate divergence here: it adopted **canonical MADR 4.x** (ADR-0157) as the project-wide ADR format, migrated a 276-ADR corpus to it (ADR-0271), added a `completed` boolean orthogonal to status (ADR-0262), built a **fork-only scriptable `agentdb index` CLI** to replace ~780 MCP round-trips (ADR-0273), and re-converged ADR causal edges onto upstream's `CausalMemoryGraph` controller (ADR-0276). **Upstream's `ruflo-adr` plugin is a far simpler 4-section ad-hoc template** with no scriptable index, no MADR, no `completed` flag, no causal-graph re-convergence. So the C4 divergence is **format/tooling FORK-AHEAD**, not brokenness-repair — and (like C2) the risk class is *demonstrated-then-but-diverged-since*, plus one inherited scope-gap regression (C2 R1) that the adr plugin is the primary consumer of.

The other five C4 plugins are **markdown thought-templates riding shared substrate** (`memory_*`, `agentdb_hierarchical-*`, `hooks_worker-dispatch`, `task_*`, `analyze_*`) — their ADRs are plugin *contracts* (ADR-0001 per plugin) documenting the substrate mapping, plus the jujutsu napi-build ADR (ADR-0150). These contracts are documentation-discipline ADRs, not patches premised on brokenness.
