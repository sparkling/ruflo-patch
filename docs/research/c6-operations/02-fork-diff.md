## Headline divergences

1. **The C6 substrate is healthy where it is shared** — `hooks_worker-*` (registry + dispatch + status + detect + cancel), `memory_*` namespace-routed (`cost-tracking`/`cost-patterns`/`observability`/`browser-sessions`), `hooks_model-route`/`-outcome`/`-stats` (real contextual-bandit learning), the 23 raw `browser_*` interaction tools (real Chromium drive), and 3 of 4 `agentdb_*` stat tools all store/recall/drive with REAL content. No C6 plugin's *shared* substrate is dead.
2. **The browser session-as-skill flow (the fork's flagship FORK-AHEAD) is dead — and dead one step earlier than upstream.** `browser_session_record` fails at step-1 `rvf create --kind browser-session` (`--kind` invalid + missing required `-d/--dimension`). Upstream's step-1 was patched (Issue #2015 → `--dimension 384`) and succeeds; **the fork did not inherit the fix**. Steps 2–4 (`trajectory-begin/step/end`) carry the SAME ruvector arg-skew as upstream (`--session-id`/`--task`/`--verdict` vs ruvector@0.2.25's `-c/--context`, `-a/-r/--reward`, `--success/--quality`). The whole `record→end→replay` flow + the `browser-sessions` AgentDB index it feeds are starved.
3. **One fork-authored observability stat tool is broken by a registry-key typo.** `agentdb_circuit_status` queries `getController('circuitBreakerController')`; the registry key is `circuitBreaker` (enabled:true). Always returns `"Circuit breaker not available"`. The fork's ADR-0238 S3 redirect points the `observe-metrics`/`observe-trace` skills at exactly these 4 stat tools as the live-introspection path — one of the four is dead. (Honest "not available" envelope, not silent-wrong.)
4. **The cost-tracker learning loop genuinely learns.** `hooks_model-route` "format json output" → `sonnet`; after one `hooks_model-outcome{model:haiku, success}` the SAME task re-routes to `haiku` (the Beta-prior flipped); `hooks_model-stats` shows the durable update (`contextualPriors:{"general:haiku":{alpha:3,beta:1}}`). Real contextual-bandit (ADR-0278), not counter-echo.

## Top FORK-REGRESSION — `browser_session_record` `rvf create` un-merged upstream fix (Issue #2015)

**Validation bar satisfied (all 5 points), with the prover's positive upstream baseline:**
1. **Production shape:** long-lived `cli.js mcp start` stdio server, 317 warm tools, real local `file://` page, `browser_session_record{url, task, session, rvf_dir}` per the live schema (`required: url, task`).
2. **Documented defaults:** the tool's own schema + the command doc (`/ruflo-browser` §2 cites `rvf create`); ruvector@0.2.25 `rvf create --help` shows `-d/--dimension` **required** and **no `--kind`**.
3. **Content not counters:** the failure is a structured `{success:false, error:"rvf create failed"}` isError envelope; **direct repro** of the exact handler command — `npx -y ruvector@0.2.25 rvf create <path> --kind browser-session` → `exit 1, error: required option '-d, --dimension <n>' not specified`. Proof the rest of the chain is sound: `rvf create <path> -d 768` → `Created … (dim=768, metric=cosine)`, then `rvf status` → real store stats. So the ONLY break at step-1 is the missing `-d` + the bogus `--kind`.
4. **Installed-dist:** traced in the installed dist `browser-session-tools.js:106` (`['rvf','create',rvfPath,'--kind','browser-session']`); upstream `git show origin/main` shows the browser session tools were hand-ported via INTEGRATION-LEDGER Batch S (ADR-122 #2041), and the fork corpus + ledger contain **zero** Issue-#2015 / `rvf create --kind` fix.
5. **Cold-vs-warm ruled out:** deterministic CLI-contract mismatch (a missing required flag) — identical on every invocation, warm or cold.

**Mechanism (root-caused):** upstream's `browser-session-tools` `rvf create` call was already patched for the `--kind` bug to pass `--dimension <n>` (the prover cites the in-code Issue #2015 comment; upstream step-1 writes a real 162B `.rvf`). The fork's hand-port (Batch S, 2026-05-18) captured an **earlier, un-patched** `rvf create … --kind browser-session` form and **never re-synced** when upstream fixed it. This is the **un-merged-half-of-an-upstream-fix class** (= C3's M-C1 / ADR-0295 R1). **C6-specific consequence:** the browser session-as-skill flow — the flagship FORK-AHEAD of ruflo-browser ADR-0001 — is dead at its very first action, one step earlier than upstream's (already-broken) flow. The fix is two-part and small: (a) `rvf create` → drop `--kind`, add `-d <dim>` (a dimension constant, e.g. 768 to match the fork's embedding model, or 384 as upstream); (b) the three trajectory calls → ruvector@0.2.25's actual shapes (`-c/--context`, `-a/-r/--reward`, `--success/--quality`) — the UPSTREAM-BROKEN-SHARED half. Disposition → the C6 re-convergence ADR (and cross-ref ADR-0293 D-series for the trajectory-skew class).
