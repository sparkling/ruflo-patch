## Headline divergences

1. **aidefence wiring is PARITY but the ENGINE is FORK-BEHIND (DA-corrected).** 6 tools, handler byte-parity, content-accurate stats, in-process learning all hold — but the fork's shipping engine (`@sparkleideas/aidefence@3.0.2-patch.938`) lacks upstream npm 3.0.3's ADR-118 detection content (0 vs 9 refs; no OVERRIDE_NOUNS window, no behave-as widening, no god/root/admin/sudo-mode pattern) → ≥2 real must-alert false-negatives on the user-facing path (DA-1, MUST-CLOSE → ADR-0297). The original "behaviourally inert" verdict came from direct-injection-only batteries; the DA's discriminating probes exposed the gap.
2. **The federation NPM package is DEAD on a fresh install — the single most-broken C5 surface (R1, top regression).** `npx -y -p @sparkleideas/plugin-agent-federation … ruflo-federation <any>` crashes at module-load (`ERR_MODULE_NOT_FOUND: @sparkleideas/agentic-flow`). EVERY federation skill/command/agent drives this exact invocation → the entire federation CLI surface is non-functional. Root: the package statically imports `agentic-flow/transport/loader` (alpha.5 ADR-104 pattern) without declaring `agentic-flow` as a dependency, while upstream alpha.16 (ADR-120) wraps it in a graceful dynamic-import loader. FORK-REGRESSION (stale-fork). Proven by root-cause: installing agentic-flow alongside → `init` succeeds (exit 0).
3. **security `defend` default TEXT-display path crashes on a detected threat (R2) — DA-SETTLED: UPSTREAM-BROKEN-SHARED.** `security defend -i "<injection>"` detects the threats then crashes rendering them: `Cannot read properties of undefined (reading 'color')`. Root-caused to an **unbound `OutputFormatter` method extraction** in the `severityColor` map. `--output json` and benign inputs are unaffected. The DA drove LIVE upstream 3.10.36's default-text path: **crashes character-identically** (`security.js:855-861` ≡ fork `:867-873`) — NOT a fork regression; a fork-side cosmetic fix (bind the methods) is recommended since it crashes the headline CLI use on every real threat.
4. **The substrate the C5 plugins ride is healthy** — all 6 `aidefence_*` + `transfer_detect-pii`, the `security scan/secrets/threats/defend(json)` CLI, the ADR-097 budget envelope (in `federation_send`), and the 3 memory namespaces (RVF-durable) all work. No C5 plugin's *core substrate* is dead — federation's break is at the package-load layer, not its logic.
5. **The divergences are overwhelmingly INHERITED from upstream (PARITY) or stale-fork (BEHIND), not fork-originating-AHEAD** — the inverse of C4. The fork carries upstream's doc-drifts (federation `send` CLI gap, `cve` honest-stub, PII-detector taxonomy over-advertisement) verbatim and adds NO fork-ahead C5 capability; its one structural divergence (federation) is a *regression from being behind*.

## FORK-REGRESSION (top) — R1: federation NPM package dead on fresh install (stale-fork, undeclared agentic-flow dep)

**The single most-broken C5 surface.** `npx -y -p @sparkleideas/plugin-agent-federation@latest ruflo-federation <any-subcommand>` crashes at module-load:
```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@sparkleideas/agentic-flow' imported from

```
EVERY federation skill (`federation-init`/`-status`/`-audit`), the `/federation` command, and the `federation-coordinator` agent drive this exact `npx -y -p` invocation → **the entire advertised federation CLI surface is non-functional on a clean Verdaccio install.**

**Validation bar (all 5 points):**
1. **Production shape:** the documented `npx -y -p @sparkleideas/plugin-agent-federation@latest ruflo-federation init` (verbatim from `federation-init/SKILL.md` step 1), fresh project, private cache.
2. **Documented entry:** traced the bin first (`feedback-trace-bin-entry`) — `package.json bin: {"ruflo-federation":"dist/bin.js"}`; the crash is at `dist/plugin.js:21` (imported by the bin chain).
3. **Content not counters:** the actual `ERR_MODULE_NOT_FOUND` stack captured; package `dependencies` = `{"@noble/ed25519":"^2.0.0"}` ONLY (agentic-flow absent from deps/peer/optional); `@sparkleideas/agentic-flow@2.0.2-alpha-patch.963` IS on Verdaccio but undeclared so npx never installs it.
4. **Installed-dist:** the published `dist/plugin.js` (line 21) does a **static top-level** `import { loadQuicTransport, getTransportCapabilities } from '@sparkleideas/agentic-flow/transport/loader'` (no `transport/` subdir, no midstream-aware-loader). 5. **Cold-vs-warm + ROOT-CAUSE PROOF:** deterministic (every invocation crashes identically). **Proof:** `npm install @sparkleideas/agentic-flow @sparkleideas/plugin-agent-federation` alongside → `node dist/bin.js init` succeeds (exit 0, "Federation initialized: node-mpzw…"), and `import('@sparkleideas/agentic-flow/transport/loader')` resolves (`WebSocketFallbackTransport`, `getTransportCapabilities`). **Mechanism (root-caused, vs the prover's positive upstream baseline):** the fork's federation package is **stale at alpha.5-patch.180** (Verdaccio `latest`; never advanced past the alpha.5 line). At alpha.5 the loader pattern was the **ADR-104 static import** of `agentic-flow/transport/loader`.
