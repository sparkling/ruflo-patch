## The central divergence axis (read first — frames every premise)

**Upstream 3.10.36** (queen's proof): `.swarm/memory.db` via **`sql.js` (WASM SQLite)** is the single source of truth — `memory_entries` (with 384-d MiniLM embeddings), `vector_indexes`, AND all relational tables (causal/hierarchical) live in one WASM-SQLite file; `graph_edges` served by `@claude-flow/ruvector-graph-node`. `memory init` help literally says "sql.js (WASM SQLite)".

**Fork (cli.415/agentdb.427):** a **two-engine split** — **native RVF** (`.swarm/memory.rvf`, Rust N-API) for the vector/memory axis (`memory_*` entries + embeddings; no `memory_entries` table) **+ native `better-sqlite3`** (`.swarm/memory.db`) for the relational axis (`causal_edges`, `hierarchical_memory`, `reasoning_patterns`, `adr_node_ids`). mpnet-768 embeddings.

So the fork's hardest divergence is **NOT "RVF replaces SQLite everywhere"** — ADR-0166a explicitly proved RVF cannot be a relational substrate ("zero relational primitives"). It is: **the fork removed the sql.js WASM path** (ADR-0091) and uses **native engines (RVF + better-sqlite3)** where upstream uses **WASM sql.js**. This is the lens for every premise below.

The mistakes are (a) divergence-necessity not re-justified against *current* upstream (M1, the big one), (b) a scope-gap regression from an otherwise-correct re-convergence (M2), and (c) staleness from upstream evolving past the fork's snapshot (M3/M4/M5).
