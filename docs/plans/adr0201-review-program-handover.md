## 1. What this program is

The 2026-05-19 soundness audit (ADR-0201) spawned a batch of remediation ADRs (0202–0218), all drafted the same day from the *static* audit slices. We are reviewing each with a **6-expert adversarial swarm** (queen + devil's advocate + 4 specialists), **one ADR at a time**, then rewriting the ADR to reflect the verdict. The recurring outcome: the static-derived drafts repeatedly proposed a *label / gate / wire* remedy that the runtime, upstream, or true inventory did not support — so most got reversed or reframed.

This produced a durable lesson, now captured as memory `feedback-remediation-adr-preflight` and as a checklist appended to ADR-0201 itself. **Apply it to every remaining ADR.**

### The pre-flight checklist (run BEFORE accepting any label/gate/wire remedy)
1. **Does the signal reach its audience?** Trace the propagation path end-to-end to the real consumer. (Recurring failure: exit codes swallowed by `continueOnError`/`ruflo-hook.sh exit 0`; `_stub` JSON-stringified into `content[0].text`; tools selected by `description` before any runtime envelope.)
2. **Did upstream already decide this?** `diff` against `/Users/henrik/source/ruvnet/ruflo/` (+ `ruvnet/agentdb`) and check upstream ADRs/issues. A fork-only gate on upstream-by-design behaviour is a perpetual merge tax.
3. **Is the premise/inventory true at runtime?** Re-derive counts/behavior from the *live* code, not the audit table. (Recurring: "9 flags"→30+; "29 regressions"→inherited; "41 tools"→11; "register the server"→server crashes on boot.)
4. **No sibling-ADR overlap?** Check the rest of the batch for the same surface/mechanism.

Default to **implement / delete / behaviour-verify at the seam that matters**, and re-converge with upstream, over label/gate/wire.
