## Cross-cutting findings

**FS_JSON_PATH_OVERRIDES recurring-gap.** Phase 2's queen-audit caught one; Phase 5 caught three more (claims/tasks/hive-mind_agents/agent_spawn). Same shape every time: cli `loadXxxStore()` direct FS read and archivist `withWrite({storeId})` resolve to different paths. **Phase 6+ recommendation:** register-time path-alignment-check as a precondition of `registerMutationHandler`, if practical without breaking the storeId abstraction.

**L1 / L2 resolution — all W-lazy (phase5-lazy-init).** Three-layer defense landed entirely under task #2: (a) async `getProcessArchivist()` getter that folds in `initProcessArchivist()` — compile-time prevention via `Promise<Archivist>` return; (c) `hasRealConfig` discriminator inside `Archivist` (`forks/agentdb/src/archivist/index.ts:279, 351-353, 622-630, 678-686`) that distinguishes real-host-config from the defensive empty-default `initialize({})` — runtime fail-loud with an actionable error message naming `initProcessArchivist()`; plus `ensureArchivistInitialized` helper for explicit-await call sites. L2 was solved by memo-clear-on-reject — a transient FS-error doesn't poison the cli's wire-up promise permanently. (Initial DA memo draft mis-attributed the `hasRealConfig` discriminator to W-typed; corrected here per phase5-typed-overload's audit-trail accuracy request.)

The notable coordination win: W-lazy **absorbed the option-(a) retrofit themselves** after 4 workers had already landed the sync `getProcessArchivist().dispatch(...)` shape. Rather than 13 workers each individually re-aligning, phase5-lazy-init shipped the async getter plus migrated all 4 already-landed files (task, daa, swarm, claims) in one coordinated change. **Infrastructure worker absorbs churn so delegation workers don't have to.** Model pattern for future phases where an architectural decision lands mid-flight after downstream work has already mirrored an earlier shape.

**DAA cross-substrate tail-call removed.** The `routeMemoryOp` side-channel writing to namespace `daa-feedback` was deleted, not migrated. Future vector-searchable adaptation-event index should be a registered archivist handler invariant, not a cli-boundary try/catch. Documented in `daa-tools.ts:283-291`.

**Capability-adapter recursion rule (new structural finding from #5).** Cli helpers that back archivist capability adapters (per Phase 4 W1/W2 wiring) CANNOT themselves dispatch through archivist — they would create a literal infinite recursion via the capability injection path. Specific instances: `routeTask` (backs `makeCliTaskRouter` for `ctx.capabilities.requireTaskRouter()`), `searchPatterns` (backs `makeCliPatternReader` for `ctx.capabilities.requirePatternReader()`). Phase 6+ rule: any new capability adapter wiring MUST audit the backing helper and exclude it from any future cli-to-archivist flip scope. V2 verifier checklist should encode this as a structural invariant.
