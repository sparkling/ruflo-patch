## What CLAUDE.md is for (and what it isn't)

CLAUDE.md is loaded into every Claude Code session as system instructions. The AI reads it before any user prompt and uses it to decide which tools to call, when to refuse, what conventions to follow, and what NOT to do.

**It is:** an imperative rule-set, a decision tree, an anti-pattern guide.
**It is not:** a USERGUIDE, a marketing brochure, a tutorial, a feature catalog.

Every line in CLAUDE.md must answer one of:
- "What MUST the AI do in situation X?"
- "What MUST the AI NOT do in situation X?"
- "How does the AI DECIDE between option A and option B?"
- "Where does the AI LOOK when it needs more context?"

If a line answers "what is feature X?" or "how do you install Y?" — that's USERGUIDE territory, delete it.

## AI-optimized CLAUDE.md principles (the rubric)

Drawn from Anthropic's published guidance + observed-effective patterns in this repo's own root `CLAUDE.md`:

1. **Imperative voice only.** `DO X`, `NEVER Y`, `ALWAYS Z`. No descriptive prose, no "Plugins are...", no "This system provides...".
2. **Front-load priority.** Most-violated rules first. Behavioral / safety rules at top. Reference material at bottom.
3. **Decision trees beat explanations.** Tables of "WHEN ... → USE ..." outperform paragraphs about features.
4. **Trigger-action pairs.** "When user asks for X capability missing from current toolset → run `ruflo plugins list`" is correct framing. "Plugins extend capabilities" is wrong framing.
5. **Anti-patterns explicit.** Every "DO" rule has more leverage when paired with the "DON'T" that motivates it. "DO NOT install plugins reflexively. Install only when user asks for a capability not provided by current tools" is one rule, two halves.
6. **Concrete commands over concepts.** `npm run release` (verbatim) > "the canonical release command".
7. **Reference, don't duplicate.** Catalogs live in USERGUIDE / `ruflo skill list` / `ruflo plugins list`. CLAUDE.md says "use the discovery command", not "here are the skills".
8. **Memory/doc pointers at the bottom.** "More context lives at `<path>`" is a one-line escape hatch from CLAUDE.md back to fuller docs when the AI hits an unfamiliar area.
9. **Terseness signals load-bearing-ness.** A bullet-rule that's 3 lines long signals "this matters". A 3-paragraph explanation signals "skip this until needed". Cut filler, padding, restated rules.
10. **Don't restate what the tool description already says.** If the rule lives in the tool's own JSONSchema description (e.g., "don't guess skill names"), it's already loaded with the tool. Restating in CLAUDE.md duplicates without adding leverage. CLAUDE.md adds value by saying *when to prefer tool A over tool B* — comparisons across tools, which no single tool description covers.

## Decision

**Three changes, content-first:**

### Change 1 — Add `toolSelectionRules()` (replaces the dead-code path entirely)

Decision tree for which tool primitive to reach for. Replaces the current `whenToUseWhat()` table by extending it; deprecates the dead `agentTypes()` and `memoryCommands()` functions in their current shape.

```markdown
## Tool Selection Rules

When you need a capability, choose in this order. Stop at the first match.

| You need to... | Use | Prefer over |
|---|---|---|
| Coordinate parallel sub-tasks | `Agent` tool with `run_in_background: true` | `swarm_init` for one-shot work |
| Convene a council on a high-stakes decision | `hive-mind_spawn` (or invoke the `hive-mind-advanced` skill) | `Agent` fan-out (no synthesis) |
| Persist patterns/decisions across sessions | `mcp__ruflo__memory_store` | Writing to MEMORY.md from in-session work |
| Recall past decisions/patterns | `mcp__ruflo__memory_search` | Asking the user to re-explain |

When the active toolset doesn't cover a capability:
1. Run `ruflo skill list` — a skill may already provide it
2. Run `ruflo plugins list` — an installable plugin may provide it
3. Only after both come up empty, build the capability inline or ask the user

Sub-agents spawned via `Agent` typically inherit the parent's `mcp__ruflo__*` toolset. For long-running sub-tasks where MCP visibility is uncertain, run a discovery probe before spawning rather than pre-fetching results.
```

### Change 2 — Add `pluginInstallRule()` (one paragraph, imperative)

Replaces the would-be "Plugin Marketplace tutorial" with the actual AI-relevant decision: when to install a plugin vs when not to.

```markdown
## Plugin Installation Rule

NEVER install plugins without explicit user confirmation. Plugins persist past the session.

Install only when ALL hold:
- User asked for a capability not covered by `ruflo skill list` or active MCP tools
- User confirmed the install

Discovery: `ruflo plugins --help`.
Install: `/plugin install ruflo-<name>@ruflo` (after `/plugin marketplace add ruvnet/ruflo`).
Tell user to run `/reload-plugins` if commands don't appear post-install.
```

### Change 3 — Strip USERGUIDE-shaped content, replace with pointers

Remove from generated CLAUDE.md:
- Catalog enumerations ("60+ agent types: coder, reviewer, tester, ..."): replaced by 1 line `Agent types catalog: \`ruflo agent list\``
- CLI command syntax (`ruflo memory store --key X --value Y --namespace Z`): replaced by 1 line `Memory CLI: \`ruflo memory --help\``
- Setup commands (`claude mcp add ...`, `ruflo daemon start`): moved to README; the AI inherits the running env, never bootstraps it
- Marketing language ("RuFlo V3"): keep header `# Claude Code Configuration` only, no product framing

Replace each removed catalog with a "where to look" pointer:

```markdown
## Reference Pointers (when you need more than this file says)

- Tool catalog: `ToolSearch` with a relevant query
- Skill catalog: `ruflo skill list`
- Plugin catalog: `ruflo plugins list`
- Agent type catalog: `ruflo agent list`
- Architecture decisions for this project: `docs/adr/`
- Cross-session memory: `~/.claude/projects/<project>/memory/MEMORY.md`
- Full feature reference: https://github.com/ruvnet/ruflo/blob/main/docs/USERGUIDE.md
```

## Acceptance criteria (content-shape, not code)

A correct CLAUDE.md from `ruflo init --template standard` MUST:

1. Contain `marketplace` / `plugin install` / `npm install` ONLY inside `## Plugin Installation Rule`
2. Contain ZERO product-marketing language ("comprehensive", "powerful", "extensive", "Nx faster than Y")
3. Contain ZERO catalog enumerations longer than 5 items inline — longer catalogs go behind a discovery command
4. Contain at least one decision-tree table (When X → Use Y)
5. Restate ZERO rules already present in a tool's JSONSchema description (per Principle 10)
6. Pass the sample-task gate: for "user asks to scan code for security issues", CLAUDE.md must let the AI reach a working tool (security-auditor agent / ruflo-security-audit plugin / `ruflo security scan` CLI) using either the harness's auto-injected tool list or one discovery command — no USERGUIDE re-read

## What this ADR is NOT proposing

- **Not proposing skill enumeration.** Skills self-advertise via session-start system-reminders (description field is the trigger logic). CLAUDE.md says "see `ruflo skill list`" only as the fallback for plugin-installable skills not yet enabled.
- **Not proposing plugin catalog.** Plugin enumeration belongs in USERGUIDE / `ruflo plugins list`, not CLAUDE.md.
- **Not proposing setup-flow content.** Setup runs before CLAUDE.md is read. README's job.
- **Not proposing template wiring.** Trivial PR after content is approved.

## Trade-offs

- **Discoverability moves to `ruflo init` post-install hints + README.** A user reading their generated CLAUDE.md never learns the marketplace exists from CLAUDE.md alone. Acceptable — that audience is the AI, not the user.
- **Setup commands move to README.** They run before CLAUDE.md is read; the AI inherits the env, never bootstraps.
- **No upstream baseline to diverge from.** Both fork and upstream generators omit plugin/skill awareness today (verified 2026-05-05). This ADR adds new content rather than removing existing — "diverges from upstream" risk is moot on this axis.

3. Should the security and performance templates strip the protocol blocks (`## Security Protocol`, `## Performance Optimization Protocol`) further? They lean toward USERGUIDE-shape too. Out of scope for this ADR — separate audit.

## Consequences

- Plugin/skill awareness lands as decision rules the AI applies, not as catalog the AI ignores.
- Acceptance criteria are content-shape, not behavioral. Mechanical pass is possible. Mitigation: criterion 6 (sample-task gate) is the real test.
- Rollback: if generated CLAUDE.md regresses behavior (e.g., AI excessively invokes `ruflo plugins list`, or stops finding skills it previously used), revert is a single commit. Watch for: spike in `ruflo plugins list` Bash invocations during the first week of the change, and whether sample-task tests still pass against fresh init.
